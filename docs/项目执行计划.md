# 项目执行计划

> 苍穹外卖增强版（Takeaway Enhanced）完整执行计划
> 定位：校招 Java 后端简历项目（单体先行 → 技术增强 → 可选微服务）
> 目标：做出有差异化、工程规范完整、面试可深挖的项目，而不是教程复刻版。

## 总时间预估（按每天有效编码 3.5–5 小时计算）

- 单体完整版（v1.0）：28–35 天
- 微服务版本（v2.0，可选）：额外 12–18 天

---

## 阶段 0：前置准备 & 项目基线（1–2 天）

- 确定环境：JDK 17、Spring Boot 3.x、Maven、MySQL 8、Redis、RabbitMQ、IDEA、Apifox、Draw.io
- 创建 GitHub 仓库：`takeaway-enhanced`
- 写好 .gitignore、README 初始版、application-dev.example.yml
- 明确需求三分类（必做 / 自主新增 / 砍掉）
- 输出 docs/需求清单.md

**提交**：`chore: 初始化项目仓库与基础规范`

---

## 阶段 1：业务梳理 + 数据库设计（2–3 天）

- 完成需求清单（基础功能 + 自主新增亮点）
- 绘制 ER 图（docs/db/er.png）
- 设计并写出完整建表 SQL（统一字段规范 + 索引 + 新增表）
- 准备初始化数据 SQL

**提交**：`docs: 完成需求清单、ER图与数据库设计`

---

## 阶段 2：基础工程骨架搭建（3–4 天）

- 创建 Spring Boot 3 项目，规范包结构
- 统一返回体、全局异常处理
- JWT 登录拦截器 + ThreadLocal 用户上下文
- Knife4j 接口文档
- 跨域、日志、Redis、MyBatis-Plus 基础配置
- 自定义基础注解预留

**验收**：能启动项目，访问 Knife4j，JWT 拦截生效。

**提交**：`feat: 完成基础工程骨架（统一返回、JWT、异常、Knife4j）`，打 tag `v0.1-skeleton`

---

## 阶段 3：核心业务模块开发（10–12 天）

按顺序开发（每模块用 feature 分支）：

1. 管理员登录 + 员工管理
2. 菜品分类管理
3. 菜品管理（上下架、图片模拟上传）
4. C 端用户 + 收货地址
5. 购物车模块
6. 订单核心模块（下单、查询、取消）【最重要】

每个模块完成后：Apifox 自测通过 → 合并回 dev → 提交一次 Git。

---

## 阶段 4：专项技术增强（差异化核心）（6–8 天）

强制优先完成以下 4 项（按顺序）：

1. 下单超卖解决方案（Redisson 分布式锁 + Redis 预减库存）
2. 订单超时自动取消（RabbitMQ 延迟队列）
3. 菜品列表 Redis 缓存 + 缓存击穿防护
4. 接口幂等 + 自定义限流注解（基于 Redis + Lua）

有余力再做：操作日志 AOP、数据权限注解、退款流程。

---

## 阶段 5：测试 + 容器化 + 文档完善（4–5 天）

- 核心 Service 单元测试（下单、库存扣减）
- 整理 Apifox 完整测试集
- 编写异常场景测试说明（docs/test.md）
- Dockerfile + docker-compose.yml（MySQL + Redis + RabbitMQ + 应用一键启动）
- 完善文档：README、docs/开发记录.md、docs/pitfall.md、docs/interview.md

**提交**：`test: 补充单元测试与异常场景说明`、`docs: 完善README、开发记录、踩坑与面试清单`，打 tag `v1.0.0`

---

## 阶段 6：微服务拆分（可选，v2.0）（12–18 天）

仅在单体 v1.0 稳定后再做。

1. 新开分支 feature/microservice
2. 拆分：user-service、goods-service、order-service、gateway
3. 接入 Nacos、Gateway、OpenFeign
4. 可选：Sentinel、Seata
5. 完成后打标签 v2.0.0

---

## Git 提交节奏总结

- 每完成一个完整功能模块或一个技术增强点 → 提交一次
- 提交信息严格使用：`feat:` `fix:` `refactor:` `docs:` `test:` `chore:`
- 重要节点打 Tag：`v0.1-skeleton` → `v1.0.0` → `v2.0.0`
- 日常在 dev 或 feature/xxx 分支开发，稳定后再合并 main

## 使用建议

1. 每天开始前看当天要完成的任务，结束后必须对应提交 GitHub。
2. 核心并发代码（锁、库存、幂等、延迟队列）必须自己能完整讲清楚。
3. 优先保证前 4 个技术增强点质量，而不是追求全部实现。
