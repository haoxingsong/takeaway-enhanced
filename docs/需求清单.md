# 需求清单

> 项目：苍穹外卖增强版（Takeaway Enhanced）
> 定位：校招 Java 后端简历项目，单体先行，差异化技术增强
> 本文档按「必做 / 自主新增 / 砍掉」三分类管理需求，作为开发范围基线。

## 一、需求三分类总览

| 分类 | 含义 | 数量 |
| --- | --- | --- |
| 必做 | 核心业务闭环，保证项目可运行、可演示 | 8 |
| 自主新增 | 差异化亮点，面试可深挖的技术增强 | 4 强制 + 3 可选 |
| 砍掉 | 范围外功能，明确不做，避免范围蔓延 | 5 |

---

## 二、必做（核心业务闭环）

| 编号 | 模块 | 功能点 | 优先级 |
| --- | --- | --- | --- |

| M6 | 收货地址 | 地址增删改查、默认地址 | P1 |
| M7 | 购物车 | 加购、减购、清空、列表 | P1 |

## 三、自主新增（差异化亮点）

### 3.1 强制优先（必须完成，按顺序）

| 编号 | 技术点 | 方案 | 解决问题 |
| --- | --- | --- | --- |
| A1 | 下单超卖 | Redisson 分布式锁 + Redis 预减库存 | 高并发下库存超卖 |
| A2 | 订单超时取消 | RabbitMQ 延迟队列 | 下单未支付超时自动关闭 |
| A3 | 菜品缓存 | Redis 缓存 + 缓存击穿防护（逻辑过期/互斥锁） | 高频读接口性能与击穿 |
| A4 | 接口幂等 + 限流 | 自定义注解 + Redis + Lua | 重复提交、接口刷量 |

### 3.2 可选增强（有余力再做）

| 编号 | 技术点 | 说明 |
| --- | --- | --- |
| B1 | 操作日志 AOP | 记录关键操作到日志表 |
| B2 | 数据权限注解 | 基于角色的数据隔离 |
| B3 | 退款流程 | 订单退款状态流转 |
| B4 | 收藏 | 用户收藏菜品 |

## 四、砍掉（范围外，明确不做）

| 编号 | 功能 | 砍掉理由 |
| --- | --- | --- |
| C1 | 真实微信登录/支付 | 需要企业资质，改为模拟，聚焦后端核心 |
| C2 | 骑手/配送调度 | 范围过大，非简历重点 |
| C3 | 多门店/连锁 | 单体阶段单店即可 |
| C4 | 财务报表/BI 统计 | 与核心链路无关 |
| C5 | 消息推送（极光等） | 第三方依赖，非核心 |

> 说明：C 端登录、支付均采用「模拟 + 接口预留」方式，保留扩展点但不做真实对接。

---

## 五、范围控制原则

1. 强制优先保证 A1–A4 的质量，而非追求功能数量。
2. 核心并发代码（锁、库存、幂等、延迟队列）必须能完整讲清原理。
3. 每完成一个模块或技术点，独立 Git 提交。
4. 需求变更须回填本文档并重新评审，防止范围蔓延。
